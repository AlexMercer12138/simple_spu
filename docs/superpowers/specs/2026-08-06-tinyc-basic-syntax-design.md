# Tiny C 基础语法扩展设计

## 1. 目标

扩展当前 MERC32 Tiny C 编译器，使其能够直接表达裸机程序中常用的文本处理、
数组初始化、更新运算和结构化控制流。重点用例是基于现有 UART 外设编写：

```c
void print(char *text);

int main(void) {
    print("hello\n");
    return 0;
}
```

本次继续沿用现有 `Lexer -> Parser -> AST -> CodeGenerator -> MERC32 assembly`
架构，不引入新的中间表示，也不重构现有 ABI。

## 2. 功能范围

### 2.1 字符字面量

字符字面量在词法阶段解码为单个 8 位整数，并在 AST 中沿用数字表达式：

```c
char a = 'a';
char newline = '\n';
unsigned char value = '\xFF';
```

支持以下转义：

- `\n`、`\r`、`\t`、`\0`
- `\\`、`\'`、`\"`
- `\a`、`\b`、`\f`、`\v`
- 1 至 3 位八进制转义
- 至少 1 位十六进制转义 `\xNN`

普通非 ASCII 源字符采用 UTF-8 编码。字符字面量解码后必须恰好是一个字节；
空字符、多字符或 UTF-8 多字节字符字面量均报错。转义值必须位于
`0x00..0xFF`。

### 2.2 字符串字面量

字符串内容按 UTF-8 编码并自动追加一个 `0` 字节。支持相邻字符串拼接：

```c
print("hello " "world\n");
```

代码生成器在函数生成前遍历完整 AST，收集字符串字节序列，对相同内容去重，
并在用户全局对象之后为每个不同字符串分配隐藏静态数组。启动代码使用 `sb`
初始化这些字节。字符串表达式生成对应静态数组首地址，类型按当前类型系统表示为
`char *`。

字符串位于可写 DLB RAM，但遵循 C 的约定，不允许程序修改字符串字面量；需要
可写文本时必须使用字符数组。编译器不增加运行时写保护。

### 2.3 数组初始化

声明初始化器扩展为表达式初始化器或一维列表初始化器：

```c
int global_values[] = {1, 2, 3};
unsigned short table[5] = {10, 20};
char message[] = "hello";
char buffer[16] = "hello";
```

规则如下：

- 支持 `char`、`unsigned char`、`short`、`unsigned short`、`int` 和
  `unsigned int` 的一维数组。
- 省略数组长度时必须提供非空列表或字符串，并根据初始化内容推导长度。
- 显式长度大于初始化项数时，其余元素初始化为零。
- 初始化项超过显式长度时报错。
- 初始化列表允许最后一个元素后带逗号。
- 字符串初始化只用于 `char` 或 `unsigned char` 数组。
- 字符数组长度必须能够容纳 UTF-8 数据及结尾 `0`。
- 全局数组的列表元素必须是整数常量表达式。
- 局部数组的列表元素可以是普通运行时表达式，按源码顺序求值一次。
- 不支持嵌套初始化列表、多维数组、指针数组或通用标量花括号初始化。

全局数组仍由启动代码逐元素写入。局部数组初始化在声明位置生成逐元素存储，
包括对未显式提供元素的清零。

## 3. 运算符扩展

### 3.1 词法和优先级

词法器使用最长匹配识别以下新符号：

```text
++ -- += -= *= /= %= &= |= ^= <<= >>= ?
```

三目表达式位于逻辑或与赋值之间，赋值及复合赋值保持右结合；前缀更新位于一元
表达式层，后缀更新位于下标之后。

### 3.2 复合赋值

支持：

```text
+= -= *= /= %= &= |= ^= <<= >>=
```

复合赋值节点保存左值、基础运算符和右值。代码生成器先计算并暂存左值地址，随后
读取旧值、计算右值、执行运算、转换回左值类型并写回。左值表达式只求值一次，
因此 `array[index++] += value` 只增加一次 `index`。

指针仅允许 `+=` 和 `-=` 整数，增量按所指元素大小缩放。其他指针复合运算报错。

### 3.3 自增和自减

支持前缀与后缀形式：

```c
++i;
--i;
value = i++;
value = i--;
ptr++;
```

操作数必须是可写左值，并且地址只计算一次。前缀形式返回写回后的值，后缀形式
返回写回前的值。指针增减按元素大小缩放，窄整数写回时继续执行现有截断和
符号/零扩展规则。

### 3.4 三目运算符

三目运算符右结合：

```c
result = condition ? yes_value : no_value;
```

条件只求值一次，仅执行被选中的分支。整数分支采用现有整数提升和通常算术转换；
兼容的对象指针分支产生指针结果。两侧类型不兼容时报错。

## 4. 控制流扩展

### 4.1 do/while

支持标准形式：

```c
do {
    body();
} while (condition);
```

循环体至少执行一次。`continue` 跳转到条件判断标签，`break` 跳转到结束标签。

### 4.2 switch/case/default

支持标准标签语法、嵌套 switch 和贯穿执行：

```c
switch (value) {
case 1:
    first();
    break;
case 2:
case 3:
    shared();
    break;
default:
    fallback();
}
```

代码生成器只计算一次 switch 控制表达式，将值暂存后依次与 case 常量比较，
命中后跳到对应标签；无匹配项时跳到 default 或 switch 结束。case/default AST
节点保持源码顺序发射，不自动插入跳转，从而保留 fallthrough。

case 值必须是整数常量表达式。每个 switch 在代码生成前独立收集标签，不进入
嵌套 switch。重复 case 或多个 default 报错。case/default 出现在 switch 外时报错。

switch 只向 `breakLabels` 压入结束标签，不修改 `continueLabels`。因此 switch
内的 `break` 退出最近的 switch，而位于外层循环中的 switch 内执行 `continue`
时仍继续最近的循环。

## 5. AST 和代码生成边界

新增的主要 AST 节点为：

- `StringExpr`
- `CompoundAssignExpr`
- `UpdateExpr`
- `ConditionalExpr`
- `DoWhileStmt`
- `SwitchStmt`
- `CaseStmt`
- 表达式/列表形式的 `Initializer`

字符字面量直接复用 `NumberExpr`。现有二元运算生成逻辑提取为可由普通二元表达式
和复合赋值共同调用的辅助方法。左值地址计算也提取为单次求值路径，供赋值、复合
赋值和更新表达式共享。

`FunctionCollector` 必须遍历所有新增语句、表达式和局部初始化器，保持调用参数
暂存区计算正确。字符串收集独立于函数栈布局，所有静态字符串地址在生成启动代码
前确定。

## 6. 错误诊断

以下情况必须抛出带源码行列的 `CompilerError`：

- 未结束的字符或字符串字面量
- 非法或越界转义
- 空、多字符或多字节字符字面量
- 无初始化器的不完整数组
- 空的长度推导初始化列表
- 数组初始化项过多、字符串无法放入字符数组
- 非字符数组使用字符串初始化
- 嵌套初始化列表
- 不可写表达式使用复合赋值或自增减
- 不支持的指针复合运算
- 重复 case、多个 default、非常量 case
- switch 外使用 case/default
- 循环和 switch 外使用 break
- 循环外使用 continue

## 7. 测试策略

### 7.1 编译器集成测试

扩展 `merc32-vsce/scripts/test-c-compiler.js`，覆盖：

- 字符及全部支持的转义
- ASCII、UTF-8、转义和相邻拼接字符串的静态字节布局
- 相同字符串去重及字符串作为函数实参、全局/局部指针初始化
- 字符串数组初始化和各整数宽度的全局/局部列表初始化
- 长度推导、补零、尾逗号和错误诊断
- 所有复合赋值、前后缀自增减及左值单次求值
- 指针更新的元素大小缩放
- 三目短路、右结合和结果类型
- do/while、switch fallthrough、default、嵌套及 break/continue 目标

每一组先加入会因当前语法缺失而失败的测试，再实施最小功能并运行通过。

### 7.2 CPU RTL 执行测试

扩展 `example/tinyc_feature_test.c`，让真实 MERC32 RTL 执行新增语法并把所有结果
汇总到现有 pass/fail 状态字。运行 `npm run test:c:rtl` 验证解析、汇编、ISA 和
运行时语义的完整链路。

### 7.3 UART 字符串测试

将 `example/tinyc_uart_test.c` 的发送接口改为接收 `char *`，并直接调用
`print("...")`。现有 UART testbench 继续逐字节核对发送内容，从而验证字符串
静态初始化、指针遍历、字符读取和 UART MMIO 写入。
