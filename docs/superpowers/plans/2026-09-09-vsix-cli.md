# MERC32 VSIX CLI Implementation Plan

**Goal:** Ship a command line compiler with the extension, requiring only Node.js and one PATH setup.

**Architecture:** Share build services and defaults between CLI and VS Code. Maintain launchers in `~/.merc32/bin` pointing at the activated extension. Existing packaging includes code and resources.

**Spec:** ../specs/2026-09-09-vsix-cli-design.md

## Work items

- [x] Add process-level CLI tests for help, version, compilation, all formats, warnings/errors, includes/defines, invalid parameters, and argument paths. Run failing tests before implementation.
- [x] Extract `buildService.ts` and `toolchainSettings.ts`; preserve `compilerService.ts` editor wrappers. Add `cli.ts` with strict flags and diagnostics. Verify CLI parity with the shared service and existing compiler tests.
- [x] Add real launcher tests covering spaces, nonzero exits, target upgrades, and missing targets. Implement `cliInstall.ts`, a launcher resource, and `cliIntegration.ts`; register activation and setup command. Verify extension integration.

Release procedure after code review: commit code/version metadata, package VSIX, compare the embedded manifest with source, test CLI from extracted VSIX, and run repository VSIX smoke. Record the resulting artifact and validation in the delivery report.
