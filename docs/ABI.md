# MERC32 Tiny C ABI 与编译约定

本文档描述当前 MERC32 Tiny C 编译器生成汇编时遵守的 ABI、内存布局和语言子集。ISA 指令格式请参考 `ISA.md`，本文只说明 C 到 MERC32 汇编/机器码之间的约定。

## 1. 编译流程

当前工具链采用两级编译：

```text
Tiny C 源码 (.c)
    ↓  merc32-vsce Tiny C compiler
MERC32 汇编 (.asm)
    ↓  MERC32 assembler
ROM 初始化文件 / Verilog ROM / HEX / BIN 等
```

Tiny C 编译器只生成 MERC32 汇编，不直接生成机器码。后续由汇编器继续处理 `.prog`、`.entry`、标签、宏和指令编码。

编译器生成的汇编入口形式如下：

```asm
.prog <moduleName>
.entry __start

__start:
    mov r13, <stack_top>
    ...
    jmp main, r14
__halt:
    jmp __halt
```

因此 C 程序必须提供 `main` 函数。`main` 返回后会落入 `__halt` 死循环。

## 2. 寄存器约定

| 寄存器 | ABI 名称 | 用途 |
|---|---|---|
| `r0` | ZERO | 硬件零寄存器，读出恒为 0，写入无效 |
| `r1` | IRQCTL | 软件可读写的中断控制寄存器；`[0]` 为使能位，`[2:1]` 为触发模式，`[31:3]` 为保留位 |
| `r2` | IVEC | 32 位中断入口字节地址；仅当程序存在有效中断处理函数时，启动代码才写入字节地址 `4` |
| `r3` | IRET | 接受中断时由硬件写入 `resolved_next_pc`；软件可读写，但不作为 C ABI 通用寄存器使用 |
| `r4` | A0 / RET | 第 1 个参数；函数返回值 |
| `r5` | A1 | 第 2 个参数 |
| `r6` | A2 | 第 3 个参数 |
| `r7` | A3 / T0 | 第 4 个参数；函数入口保存参数后可作编译器临时寄存器 |
| `r8` | T1 | 编译器临时寄存器 |
| `r9-r11` | - | 软件可读写；当前编译器后端未分配 |
| `r12` | FP | 当前函数栈帧基址 |
| `r13` | SP | 软件栈指针，位于 DLB，向低地址增长 |
| `r14` | LR | 调用返回地址，`jmp func, r14` 写入 |
| `r15` | PC | 当前 PC 专用寄存器；软件可读写，但写入不改变控制流且会被当前 PC 自动刷新；不作为普通 C 寄存器使用 |

除 `r0` 外，硬件允许软件读写 `r1-r15`。这一能力用于操作系统保存和恢复完整上下文，不会取消专用寄存器的功能约束；普通程序不得把 `r1-r3`、`r12-r15` 当作自由分配的通用寄存器。
恢复控制流必须使用 JAL、BZ 或 BNZ；编译器不得通过写 `r15` 实现跳转。

当前编译器没有暴露通用寄存器分配模型，主要通过栈槽保存局部变量、参数和表达式临时值。`r7`、`r8` 会被表达式求值、内存访问、函数调用准备等过程频繁改写。

## 3. 函数调用约定

### 3.1 参数传递

函数参数采用混合传参：

| 参数序号 | 传递位置 |
|---|---|
| 第 1 个 | `r4` |
| 第 2 个 | `r5` |
| 第 3 个 | `r6` |
| 第 4 个 | `r7` |
| 第 5 个及以后 | 调用者在 DLB 软件栈上分配参数区 |

调用者会先计算所有实参并暂存到当前栈帧的临时槽中，再布置调用参数。这样可以支持类似下面的表达式实参：

```c
five(a + 1, b, zero(), 4, a + b);
```

超过 4 个参数时，调用者在调用前执行：

```asm
mov r13, r13 - <extraBytes>
mov [r13 + 0],  arg5
mov [r13 + 4],  arg6
...
jmp callee, r14
mov r13, r13 + <extraBytes>
```

被调用函数不负责释放调用者参数区。

### 3.2 返回值

函数返回值放在 `r4`。`char`/`short` 返回值在返回前完成截断，并按声明类型
符号扩展或零扩展到 32 位；`void` 函数当前也会在返回路径中将 `r4` 置为 `0`。

### 3.3 调用与返回

函数调用使用：

```asm
jmp function_name, r14
```

函数返回使用：

```asm
jmp r14
```

`r14` 在函数 prologue 中保存到当前栈帧，epilogue 中恢复。

## 4. 栈与栈帧布局

软件栈位于 DLB 数据空间。默认 DLB 基地址为：

```text
dataBase = 0x00800000
```

默认 DLB 地址宽度为 16 个 word 地址位，因此默认栈顶为：

```text
stack_top = dataBase + (1 << (dlbAddrWidth + 2))
          = 0x00800000 + 256 KiB
```

栈向低地址增长。函数入口会分配固定大小栈帧：

```asm
mov r13, r13 - frameSize
mov [r13 + 0], r14
mov [r13 + 4], r12
mov r12, r13
```

函数返回时：

```asm
mov r14, [r12 + 0]
mov r8,  [r12 + 4]
mov r13, r12 + frameSize
mov r12, r8
jmp r14
```

当前栈帧布局：

| 偏移 | 内容 |
|---|---|
| `r12 + 0` | 保存的 `r14` |
| `r12 + 4` | 保存的旧 `r12` |
| `r12 + 8 ...` | 参数本地副本，按声明类型自然对齐 |
| 后续区域 | 局部变量、局部数组，按 1/2/4 字节自然对齐 |
| 后续区域 | 表达式临时槽，默认 32 个 word |
| 后续区域 | 调用实参暂存区 |
| `r12 + frameSize + 0` | 调用者传入的第 5 个参数 |
| `r12 + frameSize + 4` | 调用者传入的第 6 个参数 |

调用接口中的每个参数都以 32 位值传递：前 4 个参数来自 `r4-r7`，第 5 个及
之后参数各占调用者参数区中的一个 4 字节槽。被调用函数再按形参声明宽度把值
保存到自己的紧凑栈槽，因此窄形参会在入口处截断：

```asm
sb [r12 + charParamOffset], r4
sh [r12 + shortParamOffset], r5
sw [r12 + intParamOffset], r6
...
mov r7, [r12 + frameSize + 0]   // 第 5 个参数
sb [r12 + paramOffset], r7       // 按形参类型保存
```

## 5. 数据内存与全局变量

全局变量从 `dataBase` 开始顺序分配，并按元素类型自然对齐：`char` 对齐到 1
字节，`short` 对齐到 2 字节，`int` 和指针对齐到 4 字节。数组连续存放，大小为
`元素个数 * 元素大小`。

当前全局变量初始化由启动代码生成普通写内存指令完成：

```asm
mov r7, <init_value>
mov r8, <global_addr>
sb/sh/sw [r8], r7
```

全局数组当前不支持初始化列表；启动代码会按元素宽度逐项清零。

## 6. 类型与数据模型

Tiny C 使用 8/16/32 位整数和 32 位指针数据模型：

| C 类型 | 大小 | 说明 |
|---|---:|---|
| `char` | 1 字节 | 有符号 8 位 |
| `unsigned char` | 1 字节 | 无符号 8 位 |
| `short` | 2 字节 | 有符号 16 位；也接受 `short int` |
| `unsigned short` | 2 字节 | 无符号 16 位；也接受 `unsigned short int` |
| `int` | 4 字节 | 有符号 32 位 |
| `unsigned int` | 4 字节 | 无符号 32 位 |
| 指针 | 4 字节 | 32 位字节地址 |
| `void` | 0 字节 | 仅用于函数返回类型 |

读取窄对象时，`char`/`short` 使用符号扩展，`unsigned char`/`unsigned short`
使用零扩展。写入、赋值、强制转换以及窄类型返回值会截断到目标宽度。

参与普通算术、位运算、比较和移位前，四种窄整数都会提升为 32 位有符号
`int`。由于 32 位 `int` 能表示全部 16 位无符号值，`unsigned short` 之间的
除法仍使用有符号 `div`；只有提升后的类型包含 `unsigned int` 时才使用
`divu/remu`。

指针算术按所指元素大小缩放：

```c
p + 1   // char* 加 1，short* 加 2，int* 加 4
p[i]    // 等价于 *(p + i)
```

数组表达式在读值位置会退化为指向首元素的指针。取地址 `&`、解引用 `*` 和
下标 `[]` 根据目标类型生成 `lb/lbu/lh/lhu/lw` 或 `sb/sh/sw`。

## 7. volatile 与内存访问

编译器可以解析 `volatile` 类型修饰，并在当前无优化后端下保持源码中出现的内存读写顺序。常见外设访问写法：

```c
volatile unsigned int *status = (volatile unsigned int *)0x008003C0;
*status = 0x600D;
```

需要注意：当前编译器没有复杂优化 passes，`volatile` 主要作为类型系统和未来优化约束保留；普通指针访问目前也不会被优化删除。

## 8. 控制流与比较

支持的控制流包括：

- `if` / `else`
- `while`
- `for`
- `break`
- `continue`
- `goto`
- 标签语句
- `return`

比较表达式直接生成返回 `0/1` 的 `cmp` 或 `cmpu`。当操作数类型为 `unsigned int` 或指针时使用 `cmpu`；否则使用 `cmp`。条件控制流用 `bz r7, r0 + label` 或 `bnz r7, r0 + label` 测试布尔寄存器，不依赖隐藏比较标志。

逻辑表达式 `&&`、`||` 使用短路求值。

## 9. 内建函数

当前后端提供两组简单内建函数：

```c
unsigned int __load32(unsigned int addr);
unsigned int __store32(unsigned int addr, unsigned int value);
void __irq_enable(void);
void __irq_disable(void);
```

对应行为：

```c
__load32(addr)          // 读取 *(uint32_t *)addr
__store32(addr, value)  // 写入 *(uint32_t *)addr = value，并返回 value
```

普通指针已经可以完成同类操作，内建函数主要作为低层测试和显式 MMIO 访问入口。

`__irq_enable()` 和 `__irq_disable()` 分别写入 `r1=1` 和 `r1=0`，只允许在程序定义了有效 `void __irq_handler(void)` 时使用。编译器不会自动插入这两个操作。

## 10. 当前语言子集

已支持：

- 全局变量、局部变量
- `char`、`unsigned char`、`short`、`unsigned short`
- `int`、`unsigned int`、`void`
- 指针、取地址、解引用
- 局部数组、全局数组
- 函数声明与函数定义
- 多参数函数调用，超过 4 个参数走栈
- `+ - * / %` 算术、位运算、移位、比较、逻辑运算
- `if`、`while`、`for`、`break`、`continue`、`goto`、`return`
- 常量表达式形式的全局变量初始化
- C 风格 `//` 与 `/* ... */` 注释

暂不支持或限制较多：

- `long`、`struct`、`union`、`enum`
- 浮点数
- 函数指针
- 递归深度检查和栈溢出检查
- 数组初始化列表
- 数组参数语法，当前应使用指针参数
- 指针数组
- `void *`
- 标准库和运行时库

## 11. Tiny C 中断 ABI

Tiny C 将下面的精确函数签名保留为中断处理函数：

```c
void __irq_handler(void)
```

编译器会验证该保留函数的定义必须返回 `void` 且参数列表为空；签名无效时不能生成中断入口。`__irq_enable()` 和 `__irq_disable()` 也只允许在程序具有有效 `__irq_handler` 时使用。

汇编器的 `.entry __start` 只在字节地址 `0` 注入一条复位跳转 `jmp __start`，不负责设置中断向量。编译器把下面这一条且仅一条向量指令放在字节地址 `4`：

```asm
__irq_vector:
jmp __irq_handler
```

`__start` 完成全局变量初始化后，仅在程序具有有效中断处理函数时将 `r2` 设置为字节地址 `4`。

零参数内建函数 `__irq_enable()` 写入 `r1=1`，即使能中断并选择 CPU 上升沿触发模式；`__irq_disable()` 写入 `r1=0`。两者都要求程序具有有效中断处理函数。

CPU 接受中断时把 `resolved_next_pc` 写入 `r3`，自动清除 `r1[0]`，然后跳转到 `R[r2]`。硬件不保存其他寄存器、不保存比较状态，也不维护禁止嵌套的活动标志。

`__irq_handler` 使用专用的软件函数序言：除普通帧信息外，当前编译器还会在
栈中保存并恢复 `r4-r11`，epilogue 最后执行 `jmp r3` 而不是 `jmp r14`。
硬件本身不保存这些寄存器。编译器不会保存 `r1-r3`、`r12-r15` 的完整快照，
也不会隐式清除外设中断源。

需要保留 `r4-r11` 之外上下文的程序必须自行补充保存和恢复。比较结果已经是
普通寄存器中的 `0/1`，需要跨中断保留时也按普通寄存器处理。专用 epilogue
会在 `jmp r3` 前重新置位 `r1[0]`；是否允许嵌套、何时清除中断源仍由软件
决定。重复触发、嵌套覆盖 `r3` 或未清源导致的程序跑飞均由裸机软件负责。
