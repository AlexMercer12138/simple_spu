# MERC32 Tiny C ABI 与编译约定

本文档描述当前 MERC32 Tiny C 编译器生成汇编时遵守的 ABI、内存布局和语言子集。ISA 指令格式请参考 [`ISA.md`](ISA.md)，本文只说明 C 到 MERC32 汇编/机器码之间的约定。

## 当前 Aro 后端补充（2026-09-08）

下文保留了早期 Tiny C 约定；当前生产路径为 Aro C17 -> typed unit -> MERC32
IR -> `.mobj` -> 链接器，语言支持范围以 `merc32-vsce/README.md` 为准。
当前整数参数和返回值 ABI 不变，结构体/联合体按值参数和返回值采用下述地址传递约定。

- 支持 8/16/32 位整数显式转换、复合赋值、前后置自增自减、逗号表达式和 `_Generic`。
  复合赋值保留前端运算类型，在存储前完成目标类型转换，左值地址仅求值一次。
- 字符串表达式及文件作用域复合字面量使用内部静态对象；块作用域 `static`
  使用唯一内部符号并在启动阶段初始化。块作用域复合字面量位于当前函数栈帧，
  同一语法位置重复执行时复用对象并重新初始化。
- 结构体/联合体赋值复制对象内容；自动聚合初始化支持指定成员、稀疏数组和补零。
  局部字符数组字符串初始化支持补零及恰好省略终止 NUL 的数组长度。
- 结构体/联合体按值调用支持直接调用、函数指针、递归和多翻译单元链接。
  大于 16 字节的对象复制生成字节循环，复制所需的代码和临时栈槽数量不随对象大小增长。
- `string.h` 的六个内存/字符串函数由真实字节循环实现；普通 C 构建在存在未解析
  引用时加入内存运行库，用户已定义的同名函数优先。对象 API 仍显式链接。
- `merc32_irq.h` 的 `irq_save()` 返回完整 `r1` 并清除 bit 0；`irq_restore(state)`
  恢复完整 `r1`，可用于嵌套临界区。这些接口只允许直接调用。
- Aro 的移位整数提升、`_Generic` 左值保留已加入目标维护补丁与回归测试。
  `weak`/`section` 尚无目标语义，保留的属性明确报错，不会生成伪弱符号或伪自定义节。
- `optimization: 'basic'` 压缩初始化代码，简化基本块内纯计算和局部访存，按控制流
  活跃区间复用表达式临时栈槽。默认 `none`，两种模式的参数、返回值及链接 ABI 相同。
  局部对象与聚合调用缓冲区仍拥有独立存储；仅编译器内部的表达式值槽可复用。
- `basic` 将基本块内、单次定义的部分临时值保存在 `r9-r11`，寄存器不足或跨越
  调用、IRQ、volatile、填充操作及基本块边界时使用栈槽。算术操作可直接读取驻留值。
  这些寄存器仍由调用方负责处理，启动代码的 IRQ 上下文保存包含它们。
  不含调用的叶函数省略 LR 保存/恢复，仍保留帧指针及原有参数对象布局。
- `basic` 对同一编译单元内的小型叶函数进行一轮直接调用内联，再执行常量优化。
  候选无局部对象、分支和调用，最多 12 条优化后 IR 指令；每个调用方累计预算为 64 条。
  参数使用已求值的调用参数值，8/16 位参数加载保留截断及符号扩展，内存访问保留 volatile 标记。
  参数存储仍被修改或取地址使用、volatile 参数、聚合 ABI、递归及间接调用不参与本轮内联。
  未内联路径与取地址函数仍遵守原 ABI；独立对象仍包含全部函数，随后由链接裁剪决定保留范围。
- 链接器自动展开 C 代码中超过 `0xFFFF` 的直接调用、跳转和条件分支，两种优化模式均生效。
  展开后重新布局并更新符号和重定位，直到没有新增的远跳转；函数指针使用最终地址。
- `basic` 折叠已知条件分支，按入口可达性删除指令，清理空跳转链及顺序落入即可到达的跳转。
  未知条件保留两个后继，跳转环保留循环语义，`goto` 目标参与可达性分析。
  简化后重新进行临时值活跃性和寄存器分配；仅完全不可达代码中的副作用会随代码一起删除。
  本轮不做跨合流点的全局常量传播，也不根据未定义行为推断不可达路径。
- 完整 C 构建的 `basic` 模式在链接时裁剪不可达函数，包括没有入口引用的递归调用环。
  `none` 和独立对象编译保留全部函数；多对象链接可显式设置
  `{ entrySymbol: '...', gcFunctions: true, keepSymbols: ['...'] }`。
  `keepSymbols` 指定额外需要导出的入口，缺失的保留符号会报错。
  启动代码、中断调用、全局初始化以及数据中的函数指针都参与可达性分析。
  仅被已删除函数引用的外部符号无需定义，保留下来的未解析引用仍会报错。

对象的可选 `functions` 表按顺序完整划分 `text`，每项包含 `name`、`offset`、`size`。
声明该表表示每个函数可独立删除，不会顺序落入下一函数，且所有符号引用都有重定位。
C 编译器与内存运行库提供此元数据；旧对象及未声明函数边界的手写汇编整体保留。
裁剪发生在远跳转展开之前，并同步修正函数边界、标签、地址加数和重定位位置。
当前保留所有全局数据及其初始化，因此全局回调表引用的函数会保守保留。
通过固定数值地址调用的入口不形成符号引用，应使用符号重定位或 `keepSymbols`；
后者只保证入口保留，固定地址布局仍须由链接调用方安排。

## 1. 编译流程

当前工具链采用两级编译：

```text
Tiny C 源码 (.c)
    ↓  merc32-vsce Tiny C compiler
MERC32 汇编 (.asm)
    ↓  MERC32 assembler
ROM 初始化文件 / Verilog ROM / HEX / BIN 等
```

Tiny C 编译器只生成 MERC32 汇编，不直接生成机器码。后续由汇编器继续处理 `.prog`、`.org`、`.entry`、标签、宏和指令编码。

编译器生成的汇编入口形式如下：

```asm
.prog <moduleName>
.org <codeBase>        // codeBase 非零时生成
.entry __start

__start:
    mov r13, <stack_top>
    ...
    jmp main, r14
__halt:
    jmp __halt
```

因此 C 程序必须提供 `main` 函数。`main` 返回后会落入 `__halt` 死循环。`codeBase`
默认为 0；加载到非零 ILB 地址的程序必须使用实际加载地址编译。当前 `codeBase`
仍限定在 `0x00000000..0x00007FFF`（独占上界 `0x00008000`）且必须 4 字节对齐，
以保留近端复位和中断入口。这是入口位置限制，程序正文可超过 32 KiB 和 64 KiB。
链接后的代码末地址不得超过 ILB 地址区间的独占上界 `0x08000000`；实际加载容量
仍受 FPGA 的 ILB 配置和加载器分区限制。

对象的 `CALL16` / `BRANCH16` 重定位可用可选字段 `relaxationRegister` 声明该处
空闲的临时寄存器（`4..11`）。仅带此字段的超范围跳转会被展开；未标记的手写
汇编继续按原规则报告溢出。远调用/无条件跳转使用三条指令构造 32 位地址，
再间接跳转；条件分支先反向判断，用 PC 相对跳转跳过远跳转序列。
近跳转仍为一条指令。C 后端通常声明 `r8`，初始化填充循环使用 `r4`，避免
破坏 `r8` 中的指针。中断入口在保存上下文之后才执行可展开的处理函数调用。

## 2. 寄存器约定

| 寄存器 | ABI 名称 | 用途 |
|---|---|---|
| `r0` | ZERO | 硬件零寄存器，读出恒为 0，写入无效 |
| `r1` | IRQCTL | 软件可读写的中断控制寄存器；`[0]` 为使能位，`[2:1]` 为触发模式，`[31:3]` 为保留位 |
| `r2` | IVEC | 32 位中断入口字节地址；仅当程序存在有效中断处理函数时，启动代码才写入字节地址 `4` |
| `r3` | IRET | 接受中断时由硬件写入 `resolved_next_pc`；软件可读写，但不作为 C ABI 通用寄存器使用 |
| `r4` | A0 / RET | 第 1 个参数；函数返回值 |
| `r5` | A1 | 第 2 个参数 |
| `r6` | A2 | 第 3 个参数 |
| `r7` | A3 / T0 | 第 4 个参数；函数入口保存参数后可作编译器临时寄存器 |
| `r8` | T1 | 编译器临时寄存器 |
| `r9-r11` | T2-T4 | 编译器临时寄存器，调用方保存；`basic` 用于基本块内临时值驻留 |
| `r12` | FP | 当前函数栈帧基址 |
| `r13` | SP | 软件栈指针，位于 DLB，向低地址增长 |
| `r14` | LR | 调用返回地址，`jmp func, r14` 写入 |
| `r15` | PC | 当前 PC 专用寄存器；软件可读写，但写入不改变控制流且会被当前 PC 自动刷新；不作为普通 C 寄存器使用 |

除 `r0` 外，硬件允许软件读写 `r1-r15`。这一能力用于操作系统保存和恢复完整上下文，不会取消专用寄存器的功能约束；普通程序不得把 `r1-r3`、`r12-r15` 当作自由分配的通用寄存器。
恢复控制流必须使用 JAL、BZ 或 BNZ；编译器不得通过写 `r15` 实现跳转。

局部变量和参数对象使用栈槽；`none` 的表达式临时值也写回栈槽，`basic` 则优先将符合条件的
临时值保存在 `r9-r11`。`r4-r11` 为调用方保存寄存器，跨调用活跃值需要存入栈槽。
`r7`、`r8` 会被表达式求值、内存访问、函数调用准备等过程频繁改写。

## 3. 函数调用约定

### 3.0 链接重定位与控制流目标

链接器的地址、节大小和符号偏移均以字节计。布局以分类优先的顺序进行：先处理所有
对象的 `text`，再处理所有对象的 `rodata`、`data`、`bss`；每个分类内的对象节按输入
对象顺序处理。对每个存在的对象节：

```text
section_base = align_up(cursor, section.alignment)
cursor = section_base + section.size
symbol_address = section_base + symbol.offset
```

初始 `cursor` 为 `textBase`（默认 0）。`rodata` 分类沿用所有 `text` 分类处理后的
cursor。进入 `data` 分类时，若调用方提供 `dataBase`，cursor 重置为 `dataBase`；否则
沿用 `rodata` 结束后的 cursor。`bss` 分类始终沿用所有 `data` 分类处理后的 cursor；
即使没有 `data` 节，也沿用进入 `data` 分类时的 cursor。任何已布局节的地址范围重叠
都会被拒绝。重定位记录中的加数为字节加数，因此其最终目标为 `S + A`，其中 `S` 是
已布局符号的绝对字节地址，`A` 是 relocation addend。

JAL、BZ 和 BNZ 的控制流目的地址统一为：

```text
R[rs2] + zero_extend(imm16)
```

`CALL16` 和 `BRANCH16` 使用固定宽度的直接形式时，`rs2` 必须为 `r0`。因此它们
只能编码对齐的绝对字节地址 `S + A`，并且该值必须位于 `0..65535`。远距离控制流
需要的固定大小模板和可用 scratch 寄存器 ABI 尚未定义，留待后续 ABI 修订。

### 3.1 参数传递

函数参数采用混合传参：

| 参数序号 | 传递位置 |
|---|---|
| 第 1 个 | `r4` |
| 第 2 个 | `r5` |
| 第 3 个 | `r6` |
| 第 4 个 | `r7` |
| 第 5 个及以后 | 调用者在 DLB 软件栈上分配参数区 |

调用者会先计算所有实参并暂存到当前栈帧的临时槽中，再布置调用参数。这样可以支持类似下面的表达式实参：

```c
five(a + 1, b, zero(), 4, a + b);
```

超过 4 个参数时，调用者在调用前执行：

```asm
mov r13, r13 - <extraBytes>
mov [r13 + 0],  arg5
mov [r13 + 4],  arg6
...
jmp callee, r14
mov r13, r13 + <extraBytes>
```

被调用函数不负责释放调用者参数区。

### 3.2 返回值

函数返回值放在 `r4`。`char`/`short` 返回值在返回前完成截断，并按声明类型
符号扩展或零扩展到 32 位；`void` 函数当前也会在返回路径中将 `r4` 置为 `0`。

### 3.3 调用与返回

函数调用使用：

```asm
jmp function_name, r14
```

函数返回使用：

```asm
jmp r14
```

`r14` 在函数 prologue 中保存到当前栈帧，epilogue 中恢复。

### 3.4 结构体与联合体按值调用

适用于当前已支持布局及成员类型的结构体、联合体，所有大小统一使用地址传递：

- 每个聚合实参先在调用者栈帧中建立自然对齐的独立副本，再将副本地址作为一个
  32 位参数传递。不同参数使用不同副本，求值时复制一次；被调用函数可修改副本，
  `&parameter` 指向该副本，副本在本次调用期间有效。
- 聚合返回值由调用者分配自然对齐的独立结果缓冲区。其地址占用隐藏的首参数
  `r4`，所有显式参数后移一位，仍按 `r4-r7`、其后每项 4 字节栈槽的规则传递。
  被调用函数在返回前复制完整对象到该缓冲区，并在 `r4` 返回缓冲区地址。
- 参数副本与结果缓冲区互相独立。嵌套调用分别分配缓冲区；递归调用随各自栈帧
  分配。调用结果的临时对象至少保持到所在完整表达式结束。
- 调用者负责释放所有副本、结果缓冲区和栈上传参区域。当前实现将对象空间计入
  调用者固定栈帧，同一调用语法位置在循环中复用，函数退出时整体释放。
- `merc32-c-v1` 的既有标量调用约定不变；这为此前拒绝的聚合签名补充约定，
  没有兼容早期占位辅助 API 所生成代码的承诺。

例如 `struct Pair f(int a, struct Pair b, int c, int d)` 对应：

| 位置 | 内容 |
|---|---|
| `r4` | 结果缓冲区地址 |
| `r5` | `a` |
| `r6` | `b` 的独立副本地址 |
| `r7` | `c` |
| 入口时 `[r13]` | `d` |
| 返回时 `r4` | 原结果缓冲区地址 |

手写汇编必须遵守同样的副本与缓冲区规则。`npm run test:c:aggregate-calls`
以实际 CPU 仿真覆盖 C 调汇编、汇编调 C、跨翻译单元、间接和递归调用。
启动入口 `main` 和 `__irq_handler` 由启动代码直接调用，不提供参数副本或结果缓冲区，
因此其定义使用聚合参数或聚合返回值时会收到明确的后端能力诊断。

## 4. 栈与栈帧布局

软件栈位于 DLB 数据空间。默认 DLB 基地址为：

```text
dataBase = 0x08000000
```

编译器只接受 DLB 区域内的 `dataBase`（`0x08000000..0x0FFFFFFF`）和
`1..25` 的 `dlbAddrWidth`。计算得到的独占数据上界
`dataBase + (1 << (dlbAddrWidth + 2))` 不得超过 `0x10000000`；上界恰好
等于 `0x10000000` 是完整覆盖 128 MiB DLB 的合法布局。

默认 DLB 地址宽度为 16 个 word 地址位，因此默认栈顶为：

```text
stack_top = dataBase + (1 << (dlbAddrWidth + 2))
          = 0x08000000 + 256 KiB
```

栈向低地址增长。函数入口会分配固定大小栈帧：

```asm
mov r13, r13 - frameSize
mov [r13 + 0], r14
mov [r13 + 4], r12
mov r12, r13
```

函数返回时：

```asm
mov r14, [r12 + 0]
mov r8,  [r12 + 4]
mov r13, r12 + frameSize
mov r12, r8
jmp r14
```

当前栈帧布局：

| 偏移 | 内容 |
|---|---|
| `r12 + 0` | 保存的 `r14` |
| `r12 + 4` | 保存的旧 `r12` |
| `r12 + 8 ...` | 参数本地副本，按声明类型自然对齐 |
| 后续区域 | 局部变量、局部数组，按 1/2/4 字节自然对齐 |
| 后续区域 | 表达式临时槽，默认 32 个 word |
| 后续区域 | 调用实参暂存区 |
| `r12 + frameSize + 0` | 调用者传入的第 5 个参数 |
| `r12 + frameSize + 4` | 调用者传入的第 6 个参数 |

调用接口中的每个参数都以 32 位值传递：前 4 个参数来自 `r4-r7`，第 5 个及
之后参数各占调用者参数区中的一个 4 字节槽。被调用函数再按形参声明宽度把值
保存到自己的紧凑栈槽，因此窄形参会在入口处截断：

```asm
sb [r12 + charParamOffset], r4
sh [r12 + shortParamOffset], r5
sw [r12 + intParamOffset], r6
...
mov r7, [r12 + frameSize + 0]   // 第 5 个参数
sb [r12 + paramOffset], r7       // 按形参类型保存
```

## 5. 数据内存与静态数据

DLB 静态区从 `dataBase` 开始，布局顺序固定为：

1. 用户全局对象按声明顺序分配；每个对象先按元素类型自然对齐，`char` 对齐到
   1 字节，`short` 对齐到 2 字节，`int` 和指针对齐到 4 字节。数组连续存放，
   大小为 `元素个数 * 元素大小`。
2. 所有用户全局对象之后紧接隐藏字符串池。每个池项依次存放 UTF-8 payload
   和一个 NUL 字节；完整 payload 相同的字符串共用同一地址。

全局标量、全局数组和字符串池都由 `__start` 中的普通写内存指令初始化，不依赖
ROM 数据复制机制：

```asm
mov r7, <init_value>
mov r8, <global_addr>
sb/sh/sw [r8], r7
```

标量及一维 `char`、`unsigned char`、`short`、`unsigned short`、`int`、
`unsigned int` 数组分别使用与对象宽度一致的 `sb`、`sh` 或 `sw`。未提供初始化
器的全局对象写零；数组列表中未显式提供的尾部元素也写零。全局数组初始化列表的
显式元素必须是整数常量表达式。

显式数组长度只接受单个正整数数值字面量，数值可写为十进制、十六进制或二进制；
括号、标识符和运算表达式均不受支持。空括号 `[]` 不携带长度，只能由紧随其后的
非空列表或字符串初始化器推导完整数组类型。

`char` / `unsigned char` 数组可用字符串初始化。编译器将 UTF-8 payload、NUL
和固定容量中的剩余零直接写入数组；仅作为数组初始化器出现的字符串不会在隐藏池
中再生成副本。省略数组长度时，非空列表按元素数推导，字符串按 payload 字节数
加 1 推导；固定长度必须容纳所有列表项或完整的 payload 加 NUL。

局部数组位于函数栈帧，不属于上述 DLB 静态布局。它们在执行到声明时初始化：
列表表达式按源码顺序各求值一次并逐项存储，然后清零剩余元素；字符数组的字符串
初始化同样写入 UTF-8 payload、NUL 和剩余零。初始化列表允许尾逗号。

字符串表达式产生隐藏池项首地址，类型为 `char *`，可初始化全局/局部指针或
作为函数实参。字符串池位于普通可写 DLB RAM，ABI 只约定字符串字面量不得修改；
硬件和编译器都不提供运行时写保护。

## 6. 类型与数据模型

Tiny C 使用 8/16/32 位整数和 32 位指针数据模型：

| C 类型 | 大小 | 说明 |
|---|---:|---|
| `char` | 1 字节 | 有符号 8 位 |
| `unsigned char` | 1 字节 | 无符号 8 位 |
| `short` | 2 字节 | 有符号 16 位；也接受 `short int` |
| `unsigned short` | 2 字节 | 无符号 16 位；也接受 `unsigned short int` |
| `int` | 4 字节 | 有符号 32 位 |
| `unsigned int` | 4 字节 | 无符号 32 位 |
| 指针 | 4 字节 | 32 位字节地址 |
| `void` | 0 字节 | 不能定义对象；可作函数返回类型，在形参列表中只能独占为 `(void)` 以表示无形参，也可作显式丢弃值的转换目标 |

读取窄对象时，`char`/`short` 使用符号扩展，`unsigned char`/`unsigned short`
使用零扩展。写入、赋值、强制转换以及窄类型返回值会截断到目标宽度。

参与普通算术、位运算、比较和移位前，四种窄整数都会提升为 32 位有符号
`int`。由于 32 位 `int` 能表示全部 16 位无符号值，`unsigned short` 之间的
除法仍使用有符号 `div`；只有提升后的类型包含 `unsigned int` 时才使用
`divu/remu`。

指针算术按所指元素大小缩放：

```c
p + 1   // char* 加 1，short* 加 2，int* 加 4
p[i]    // 等价于 *(p + i)
```

数组表达式在读值位置会退化为指向首元素的指针。取地址 `&`、解引用 `*` 和
下标 `[]` 根据目标类型生成 `lb/lbu/lh/lhu/lw` 或 `sb/sh/sw`。

字符和字符串字面量共用转义规则：`\n`、`\r`、`\t`、`\0`、`\\`、`\'`、
`\"`、`\a`、`\b`、`\f`、`\v`、1 至 3 位八进制转义，以及至少 1 位十六
进制转义 `\x...`。转义值限制为一个字节。普通非 ASCII 源字符按 UTF-8 编码；
字符字面量解码后必须恰好为 1 字节，字符串则保留全部 UTF-8 字节。相邻字符串
先合并 payload，再使用一个结尾 NUL。

### 6.1 复合赋值与更新表达式

支持 `+= -= *= /= %= &= |= ^= <<= >>=` 以及前缀/后缀 `++ --`。后端先计算并
暂存左值地址，再读取旧值、计算新值并写回，因此变量、解引用或下标左值的地址只
求值一次；例如 `array[index++] += value` 只更新一次 `index`。

复合赋值和更新的结果在写回前转换到左值类型。前缀 `++` / `--` 返回写回后的
值，后缀形式返回写回前的值。指针仅允许 `+=`、`-=`、`++`、`--`，右侧增量
必须是整数，并按所指类型的 1/2/4 字节大小缩放；其他指针复合运算不受支持。

### 6.2 条件表达式

`?:` 的优先级位于逻辑或和赋值之间，按右结合解析。条件只求值一次，运行时只
执行被选中的分支。两个整数分支使用现有整数提升和通常算术转换；两个同类型、
同指针层级的对象指针产生该指针类型，指针也可以和值为零的整数常量表达式组合。
非零整数不能与指针组合。

两个分支必须都产生值或都为 `void`。双 `void` 条件表达式可作为表达式语句，
或在显式转换为 `void` 等丢弃结果的上下文中执行；不能用于初始化、赋值、返回值、
函数实参或其他需要值的运算。

## 7. volatile 与内存访问

编译器保留 `volatile` 访问标记，`none` 与 `basic` 模式均保持内存访问顺序。常见外设访问写法：

```c
volatile unsigned int *status = (volatile unsigned int *)0x080003C0;
*status = 0x600D;
```

`basic` 的优化事实不跨越 volatile 访问、函数调用或 IRQ 操作；此阶段不会删除普通指针读取，
不会合并、重排或消除内存写入。填充初始化仍按字节顺序执行，并跳过稍后写入的地址重定位位置。

## 8. 控制流与比较

支持的控制流包括：

- `if` / `else`
- `while`
- `do` / `while`
- `for`
- `switch` / `case` / `default`
- `break`
- `continue`
- `goto`
- 标签语句
- `return`

比较表达式直接生成返回 `0/1` 的 `cmp` 或 `cmpu`。当操作数类型为 `unsigned int` 或指针时使用 `cmpu`；否则使用 `cmp`。条件控制流用 `bz r7, r0 + label` 或 `bnz r7, r0 + label` 测试布尔寄存器，不依赖隐藏比较标志。

逻辑表达式 `&&`、`||` 使用短路求值。

`do` / `while` 先执行循环体再判断条件，因此循环体至少执行一次；其中
`continue` 跳到条件判断，`break` 跳到循环结束。

`switch` 控制表达式必须为整数类型且只求值一次。后端将其提升并暂存，然后按
源码顺序逐个比较 `case`；`case` 必须是整数常量表达式，转换到提升后的控制类型
后检查重复值。无匹配项时跳到 `default`，没有 `default` 时跳到末尾。case/default
标签按源码顺序发射且不插入隐式跳转，因此保留 fallthrough；当前不生成跳转表。

`break` 退出最近的循环或 `switch`。`switch` 不建立 `continue` 目标，因此外层
循环内嵌 `switch` 时，其中的 `continue` 仍继续最近的循环。嵌套 `switch` 各自
收集 case/default，不会混用标签或重复值检查范围。

## 9. 内建函数

当前后端提供两组简单内建函数：

```c
unsigned int __load32(unsigned int addr);
unsigned int __store32(unsigned int addr, unsigned int value);
void __jump(unsigned int addr);
void __irq_enable(void);
void __irq_enable_level(void);
void __irq_disable(void);
```

对应行为：

```c
__load32(addr)          // 读取 *(uint32_t *)addr
__store32(addr, value)  // 写入 *(uint32_t *)addr = value，并返回 value
__jump(addr)             // 不返回，使用寄存器间接跳转到字节地址 addr
```

普通指针已经可以完成同类操作，内建函数主要作为低层测试和显式 MMIO 访问入口。
`__jump` 只接受一个整数地址，不能用于需要返回值的表达式；它用于 bootloader 等
必须在运行时选择入口地址的底层程序。

`__irq_enable()`、`__irq_enable_level()` 和 `__irq_disable()` 分别写入
`r1=1`、`r1=5` 和 `r1=0`。三者只允许在程序定义了有效
`void __irq_handler(void)` 时使用；编译器不会自动插入这些操作。

- 全局变量、局部变量

- 指针、取地址、解引用
- 字符字面量、UTF-8 字符串、相邻字符串拼接和隐藏静态字符串池

## 11. Tiny C 中断 ABI

Tiny C 将下面的精确函数签名保留为中断处理函数：

```c
void __irq_handler(void)
```

编译器会验证该保留函数的定义必须返回 `void` 且参数列表为空；签名无效时不能生成中断入口。`__irq_enable()`、`__irq_enable_level()` 和 `__irq_disable()` 也只允许在程序具有有效 `__irq_handler` 时使用。

汇编器的 `.entry __start` 在当前 `codeBase` 注入一条入口跳转 `jmp __start`，不负责
设置中断向量。编译器把下面这一条且仅一条向量指令放在 `codeBase + 4`：

```asm
__irq_vector:
jmp __irq_handler
```

`__start` 完成全局变量初始化后，仅在程序具有有效中断处理函数时将 `r2` 设置为
字节地址 `codeBase + 4`。

零参数内建函数 `__irq_enable()` 写入 `r1=1`，即使能中断并选择 CPU
上升沿触发模式；`__irq_enable_level()` 写入 `r1=5`，即使能中断并选择
CPU 高电平触发模式，适用于 `apb_intc` 等高有效控制器输出；
`__irq_disable()` 写入 `r1=0`。三者都要求程序具有有效中断处理函数。

CPU 接受中断时把 `resolved_next_pc` 写入 `r3`，自动清除 `r1[0]`，然后跳转到 `R[r2]`。硬件不保存其他寄存器、不保存比较状态，也不维护禁止嵌套的活动标志。

`__irq_handler` 使用专用的软件函数序言：除普通帧信息外，当前编译器还会在
栈中保存并恢复 `r4-r11`，epilogue 最后执行 `jmp r3` 而不是 `jmp r14`。
硬件本身不保存这些寄存器。编译器不会保存 `r1-r3`、`r12-r15` 的完整快照，
也不会隐式清除外设中断源。

需要保留 `r4-r11` 之外上下文的程序必须自行补充保存和恢复。比较结果已经是
普通寄存器中的 `0/1`，需要跨中断保留时也按普通寄存器处理。专用 epilogue
会在 `jmp r3` 前重新置位 `r1[0]`；是否允许嵌套、何时清除中断源仍由软件
决定。重复触发、嵌套覆盖 `r3` 或未清源导致的程序跑飞均由裸机软件负责。
