# APB 中断控制器中文编程手册

## 1. 模块概述

`apb_intc` 是一个可参数化的 APB 中断控制器，可汇聚 1 至 32 路中断源并产生
一个组合中断输出。每路中断源可在例化时独立配置为高电平、低电平、上升沿或
下降沿触发，并具有独立的粘滞待处理位和使能位。

控制器提供原子置位、清零寄存器，便于软件在不执行读改写的情况下管理使能和
待处理状态。仲裁器采用固定优先级，编号最小的已使能待处理中断优先，并通过
`ACTIVE` 寄存器返回其编号。

## 2. 参数与接口

### 2.1 参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `IRQ_COUNT` | `1` | 有效中断源数量，支持范围为 1 至 32 |
| `IRQ_MODE[63:0]` | `64'd0` | 每路中断源的触发模式，每路占 2 位 |

中断源 `n` 的模式由 `IRQ_MODE[2*n +: 2]` 决定：

| 编码 | 触发模式 | 原始事件条件 |
|---:|---|---|
| `00` | 高电平 | `irq_sources[n] == 1` |
| `01` | 低电平 | `irq_sources[n] == 0` |
| `10` | 上升沿 | 当前为 `1`，上一个 `PCLK` 采样值为 `0` |
| `11` | 下降沿 | 当前为 `0`，上一个 `PCLK` 采样值为 `1` |

例如，4 路控制器依次配置为高电平、低电平、上升沿和下降沿时，可使用：

```verilog
apb_intc #(
    .IRQ_COUNT(4),
    .IRQ_MODE({56'd0, 2'b11, 2'b10, 2'b01, 2'b00})
) u_apb_intc (...);
```

`IRQ_MODE` 是硬件例化参数，软件只能读取，不能在运行时修改。超出
`IRQ_COUNT` 的模式位和寄存器位均被屏蔽为零。

### 2.2 端口

| 端口 | 方向 | 说明 |
|---|---|---|
| `s_apb_pclk` | 输入 | APB 和中断采样时钟 |
| `s_apb_presetn` | 输入 | 同步低有效复位 |
| `s_apb_psel` | 输入 | APB 从机选择 |
| `s_apb_penable` | 输入 | APB 访问阶段指示 |
| `s_apb_pwrite` | 输入 | `1` 为写，`0` 为读 |
| `s_apb_paddr[31:0]` | 输入 | APB 字节地址 |
| `s_apb_pwdata[31:0]` | 输入 | APB 写数据 |
| `s_apb_pstrb[3:0]` | 输入 | APB 写字节选通，位 n 控制 `s_apb_pwdata[8*n +: 8]` |
| `s_apb_pready` | 输出 | 恒为 `1`，访问不插入等待周期 |
| `s_apb_pslverr` | 输出 | 恒为 `0` |
| `s_apb_prdata[31:0]` | 输出 | APB 组合读数据 |
| `irq_sources[IRQ_COUNT-1:0]` | 输入 | 外部中断源，位号同时作为中断 ID |
| `interrupt` | 输出 | 所有已使能待处理位的逻辑或 |

## 3. 工作原理

### 3.1 原始事件与待处理状态

每路输入先按照 `IRQ_MODE` 转换为原始事件 `RAW[n]`。高、低电平模式的原始
事件在有效电平持续期间保持为 `1`；上升沿、下降沿模式把相邻两个 `PCLK`
采样值的变化转换为一个事件。

硬件把原始事件锁存到粘滞的 `PENDING` 寄存器：

```text
PENDING = PENDING | RAW
```

事件记录不受 `ENABLE` 影响。某路中断被屏蔽时发生的事件仍会置位
`PENDING`，以后使能该位会立即参与中断输出。

### 3.2 中断输出与优先级

中断输出为组合逻辑：

```text
interrupt = |(PENDING & ENABLE)
```

`ACTIVE` 从 `PENDING & ENABLE` 中选择编号最小的置位位，因此中断 ID 0 的
优先级最高，ID `IRQ_COUNT-1` 的优先级最低。仲裁只负责报告当前最高优先级 ID，
不会自动清除待处理位，也不支持嵌套或优先级重编程。

## 4. APB 访问行为

`s_apb_pready` 恒为 `1`，控制器不会插入等待周期。读数据是由当前地址和内部
状态直接产生的组合值；写操作在 `s_apb_psel && s_apb_penable &&
s_apb_pwrite` 成立的 `PCLK` 上升沿生效。

寄存器按 32 位对齐，硬件仅使用 `s_apb_paddr[7:0]` 进行完整字节偏移译码。
因此寄存器窗口每 256 字节镜像一次，上层地址译码器应负责选择正确的外设基址。
未定义或未对齐地址读取返回零，写入无效，`s_apb_pslverr` 始终为 `0`。

所有可写寄存器均支持 APB4 字节选通。`s_apb_pstrb[n]` 只允许对应字节中的位
更新或触发副作用，未选中的字节保持不变；`s_apb_pstrb=4'b0000` 的写传输正常
完成，但没有软件可见副作用。全 32 位写使用 `4'b1111`。

## 5. 寄存器总表

| 偏移 | 寄存器 | 访问 | 复位值 | 说明 |
|---:|---|---|---:|---|
| `0x00` | `RAW` | R | 动态 | 当前原始事件状态 |
| `0x04` | `PENDING` | R | `0x0000_0000` | 粘滞待处理状态 |
| `0x08` | `ENABLE` | R/W | `0x0000_0000` | 中断使能掩码 |
| `0x0C` | `ENABLE_SET` | W1S | - | 原子置位 `ENABLE`；读取返回零 |
| `0x10` | `ENABLE_CLEAR` | W1C | - | 原子清零 `ENABLE`；读取返回零 |
| `0x14` | `PENDING_SET` | W1S | - | 软件置位 `PENDING`；读取返回零 |
| `0x18` | `PENDING_CLEAR` | W1C | - | 软件清零 `PENDING`；读取返回零 |
| `0x1C` | `ACTIVE` | R | 动态 | 当前最高优先级已使能待处理中断 |
| `0x20` | `MODE_LOW` | R | 参数值 | 中断 0 至 15 的触发模式 |
| `0x24` | `MODE_HIGH` | R | 参数值 | 中断 16 至 31 的触发模式 |

除另有说明外，位号 `n` 对应中断源 `irq_sources[n]`；`n >= IRQ_COUNT` 的位读取
为零，写入无效。

## 6. 寄存器说明

### 6.1 RAW，偏移 `0x00`

| 位 | 名称 | 访问 | 说明 |
|---:|---|---|---|
| `[IRQ_COUNT-1:0]` | `RAW` | R | 经过触发模式转换后的当前原始事件 |
| `[31:IRQ_COUNT]` | - | R | 保留，读取为零 |

`RAW` 不经过使能掩码，也不是粘滞状态。对于边沿模式，相应位从输入发生目标
变化起保持有效，直到下一个 `PCLK` 上升沿更新历史样本；这段时间可能短于一个
完整时钟周期。软件通常应读取 `PENDING`，避免因轮询间隔而漏掉边沿。对于电平
模式，`RAW` 直接反映当前有效条件。

### 6.2 PENDING，偏移 `0x04`

| 位 | 名称 | 访问 | 说明 |
|---:|---|---|---|
| `[IRQ_COUNT-1:0]` | `PENDING` | R | 每路中断的粘滞待处理状态 |
| `[31:IRQ_COUNT]` | - | R | 保留，读取为零 |

`PENDING` 本身为只读寄存器。软件通过 `PENDING_SET` 和 `PENDING_CLEAR` 修改其
状态。复位会清除全部待处理位。

### 6.3 ENABLE、ENABLE_SET 与 ENABLE_CLEAR

三个寄存器控制同一个使能状态：

| 偏移 | 寄存器 | 写入效果 |
|---:|---|---|
| `0x08` | `ENABLE` | 选中字节按写数据整体覆盖 |
| `0x0C` | `ENABLE_SET` | 写 `1` 置位对应使能位，写 `0` 保持 |
| `0x10` | `ENABLE_CLEAR` | 写 `1` 清零对应使能位，写 `0` 保持 |

`ENABLE` 可读，另外两个命令寄存器读取返回零。原子置位和清零适合多个软件
上下文分别管理不同中断源，可避免 `ENABLE` 读改写覆盖其他上下文的更新。

使能位只控制 `interrupt` 和 `ACTIVE`，不会阻止事件进入 `PENDING`。因此在
打开某路中断前，软件通常应先清除不再需要的历史待处理状态。

### 6.4 PENDING_SET 与 PENDING_CLEAR

| 偏移 | 寄存器 | 写入效果 |
|---:|---|---|
| `0x14` | `PENDING_SET` | 写 `1` 置位对应待处理位，写 `0` 保持 |
| `0x18` | `PENDING_CLEAR` | 写 `1` 清零对应待处理位，写 `0` 保持 |

两个寄存器读取均返回零。`PENDING_SET` 可用于软件触发中断或测试中断处理路径。
`PENDING_CLEAR` 用于中断服务完成后的应答。

硬件原始事件与 `PENDING_CLEAR` 同拍发生时，事件置位优先：

```text
PENDING = (PENDING & ~clear_bits) | RAW
```

因此，对仍保持有效的高电平或低电平中断执行清零，待处理位不会持续为零。服务
程序必须先消除外部中断条件，或先屏蔽该路中断，再根据系统策略清除待处理位。

### 6.5 ACTIVE，偏移 `0x1C`

| 位 | 名称 | 访问 | 说明 |
|---:|---|---|---|
| `[4:0]` | `ACTIVE_ID` | R | 当前最高优先级中断 ID |
| `[30:5]` | - | R | 保留，读取为零 |
| `31` | `ACTIVE_VALID` | R | `1` 表示 `ACTIVE_ID` 有效 |

只有同时在 `PENDING` 和 `ENABLE` 中置位的中断才参与仲裁。没有符合条件的中断
时，`ACTIVE_VALID=0` 且 `ACTIVE_ID=0`；软件必须先检查有效位，不能仅凭 ID 0
判断存在中断。

读取 `ACTIVE` 没有确认或清除副作用。同一时刻有多个中断时，软件清除当前 ID
的 `PENDING` 后，`ACTIVE` 会组合地更新为下一个编号最小的已使能待处理中断。

### 6.6 MODE_LOW 与 MODE_HIGH

两个只读寄存器返回经过 `IRQ_COUNT` 屏蔽后的 `IRQ_MODE` 参数：

| 寄存器 | 位域 | 对应中断源 |
|---|---|---|
| `MODE_LOW` | `[2*n+1:2*n]` | `n = 0..15` |
| `MODE_HIGH` | `[2*m+1:2*m]` | `m = 0..15`，对应中断 ID `m+16` |

每个 2 位字段的编码与 2.1 节相同。超出 `IRQ_COUNT` 的字段读取为零。软件可在
启动时读取这两个寄存器，确认硬件集成时选择的触发模式。

## 7. 复位与边沿检测

`s_apb_presetn` 在 `s_apb_pclk` 上升沿同步生效。复位会清零 `PENDING`、
`ENABLE` 和边沿检测使用的上一拍输入样本；`IRQ_MODE` 是例化参数，不受复位
影响。

复位释放后的第一个有效采样需要特别注意：

- 上升沿模式的历史样本初始为 `0`。若输入在复位释放时已经为高，硬件会把它
  识别为一次上升沿；
- 下降沿模式的历史样本初始为 `0`。若输入在复位释放时已经为低，不会产生一次
  下降沿，必须先采样到高电平后再变低；
- 低电平模式在输入为低时会立即形成原始事件，并置位待处理状态；
- 高电平模式在输入为高时会立即形成原始事件，并置位待处理状态。

`irq_sources` 没有内部双触发器同步器。若某个中断源不与 `s_apb_pclk` 同步，
集成设计必须在控制器外部完成时钟域同步；脉冲源还必须保证同步后能够被至少一个
采样边沿捕获。

## 8. 编程指导

以下伪代码假定 `INTC` 指向中断控制器寄存器基地址。

### 8.1 初始化

```c
/* 初始化期间先关闭全部中断，再丢弃复位后累积的状态 */
INTC->ENABLE = 0;
INTC->PENDING_CLEAR = 0xffffffffu;

/* 根据系统需求使能中断源；原子置位不会影响其他已使能位 */
INTC->ENABLE_SET = UART_IRQ_MASK | TIMER_IRQ_MASK;
```

如果使用电平触发，应在清除 `PENDING` 前确保外设端的中断条件已经撤销，否则
相应待处理位会立即重新置位。

### 8.2 固定优先级中断服务

```c
void intc_isr(void)
{
    for (;;) {
        uint32_t active = INTC->ACTIVE;
        uint32_t id;

        if ((active & (1u << 31)) == 0)
            break;

        id = active & 0x1fu;
        service_irq(id);                 /* 先处理并撤销外设中断条件 */
        INTC->PENDING_CLEAR = 1u << id;  /* 再应答控制器 */
    }
}
```

循环读取 `ACTIVE` 可按固定优先级依次处理全部待处理中断。若高优先级电平条件
一直不撤销，它会持续占据 `ACTIVE`，低优先级中断可能长期得不到服务。

### 8.3 临时屏蔽与恢复

```c
INTC->ENABLE_CLEAR = DEVICE_IRQ_MASK;
/* 执行不能被该设备中断打断的操作 */
INTC->ENABLE_SET = DEVICE_IRQ_MASK;
```

屏蔽期间发生的事件仍会记录到 `PENDING`。如果恢复使能时不希望处理这些历史
事件，应在重新使能前先处理外设条件并写 `PENDING_CLEAR`。

### 8.4 软件触发

```c
INTC->ENABLE_SET = SOFTWARE_IRQ_MASK;
INTC->PENDING_SET = SOFTWARE_IRQ_MASK;
```

软件置位与硬件事件使用相同的 `PENDING`、优先级和使能路径。清除方法也相同。

## 9. 使用限制与检查清单

- `IRQ_COUNT` 必须在 1 至 32 范围内；
- 中断 0 优先级最高，优先级不可由软件修改；
- `IRQ_MODE` 在硬件例化时确定，软件只读；
- `irq_sources` 不包含内部时钟域同步，异步源必须在外部同步；
- `RAW` 是瞬时状态，可靠的软件处理应以粘滞的 `PENDING` 为准；
- 中断使能只屏蔽输出，不屏蔽事件记录；
- 读取 `ACTIVE` 不会自动应答中断，软件必须写 `PENDING_CLEAR`；
- 电平条件持续有效时，待处理位清除后会立即或在下一拍重新置位；
- 硬件事件与 `PENDING_CLEAR` 同拍发生时，事件置位优先；
- 长期未撤销的高优先级电平中断可能使低优先级中断饥饿；
- 地址高于位 7 的部分不参与寄存器译码，寄存器窗口每 256 字节镜像；
- 未定义地址不会产生 `PSLVERR`。
